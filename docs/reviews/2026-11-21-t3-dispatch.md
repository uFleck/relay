- **What changed** — Migration `0010` adds `dispatch_attempts` with partial unique indexes giving a Task at most one open attempt or bound thread and making a thread id unique across Tasks. Core `t3_dispatch` owns the frozen inputs (attempt ULID, project id and T3 selector, resolved data directory, Task line, Brief revision, optional base ref, neutral `Relay Task <attempt ULID>` title, timestamp) and the four states `launching`, `launch_failed`, `reconcile_required`, `bound`; a known failure preserves the Brief and approval for one manual Retry, an uncertain result fences every further start, and a complete identity plus `dispatched` commit together. The claim rechecks the same readiness gates as the Task view inside one `BEGIN IMMEDIATE` transaction; `dispatch_readiness` now has one store-backed implementation shared by both callers. Startup turns abandoned launches into uncertain attempts, adopts a unique exact attempt-title match only after `show` confirms project identity, and leaves known failures for the user.
  - `t3_cli` resolves an absolute launcher on PATH or in the T3 home's `bin`, prefers the bundled Electron executable and CLI script parsed from the shim, and otherwise invokes a static `cmd.exe /D /V:OFF /S /C ""%RELAY_T3_CMD%" "%RELAY_T3_ARG_n%"..."` wrapper via `raw_arg` with every untrusted value set as a child environment variable and expanded once. A trailing backslash run is doubled for the native argv tokenizer; quotes and CR/LF/NUL are rejected. The Brief goes to UTF-8 stdin. Output is bounded, deadlines are 30 s for start and 15 s for show/list, windows are hidden, and a Job Object owns the process tree and is terminated and dropped after the wrapper exits and before the pipe readers join. Launch classification treats an exact server-stopped, project-not-found or unsupported-version diagnostic as a known failure; timeouts, lost/malformed results and unrecognised errors require reconciliation.
  - `dispatch` runs all CLI work on `spawn_blocking`, saves a validated thread id immediately, hydrates a missing run id or link with read-only `show`, and commits identity with `dispatched`. Cancellation releases only the UI wait; a late response still links the thread. Thin IPC commands `v2_dispatch_{view,retry,check,link,cancel}` feed a `DispatchPanel` in the Task sheet with **Retry**, **Check again** and **Link existing thread** (the last requires the user to confirm they compared the first message with the frozen Brief). Trigger points are Composer save, project assignment, Wait Go, Grill closing Go and startup.
