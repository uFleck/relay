## What changed

`relay_core::v2::composer` parses a submission without a provider. `??` is matched before
`?` and `!` and only at column one; a sigil needs no following space. CRLF and lone CR are
normalized to LF and each line keeps its original text. Recognised GitHub PR/issue URLs,
ClickUp card URLs and Slack permalinks become ordered, link-only References on their own
line; other URLs stay text. Explicit first `+slug` wins, even when unknown; with no token,
only the first GitHub Reference's `owner/repo` is matched against the v2 registry. Unresolved
Tasks save with a null project. Act and Wait create `briefing` Tasks, Grill creates
`grilling`; `needs project` stays a dispatch gate for a later issue.

`V2Store::save_note` now projects the Note body from plain lines only. Directive lines keep
their raw text and stable ids in `note_lines`, and their Tasks keep a frozen `original_line`
and copied References, so promotion and later edits do not lose data.

Two thin async commands, `v2_composer_save({request})` and `v2_task_assign_project({taskId,
projectId})`, are registered in `lib.rs`. Both emit `relay://v2-change` after commit. Errors
use the existing `{kind, message}` shape; the frontend wrapper for writes calls `invoke`
directly, so a missing command or stale revision is never swallowed into a mock success.
`src/ipc.ts` also exports typed v2 snapshot, Note, line, Task, project, settings and request
shapes.

One `Composer` component is mounted in a v2 capture pane on the Notes route and in the
expanded hover panel. It supports Ctrl+Enter, a single-submit guard, a retained create key
for retries, text retention on failure, and explicit reload after a stale revision. Edit
mode sends fields keyed by saved `lineId`, with add/remove line controls. The hover opens
the Composer through `hoverFocus`, keeps the panel open while it is focused or saving, and
bounds its input inside the panel. The global hotkey still summons the main window.

## Actual IPC and UI contracts

- `v2_notebook_snapshot()` → `{ notes, projects, settings }`; each Note has
  `{ id, revision, source, body, createdAt, updatedAt, lines, tasks }`.
- `v2_composer_save({ request })` where request is
  `{ kind: "create", submissionKey, text }` or
  `{ kind: "edit", noteId, expectedRevision, lines: [{ lineId, text }] }`.
  Returns the saved Note; every error propagates.
- `v2_task_assign_project({ taskId, projectId })` returns the updated Task; a different
  second project is rejected by the store.
- Both writes emit `relay://v2-change` with the Note id. The Notes capture pane listens and
  reloads the snapshot.

  The seed statement for the disposable DB must use
  `INSERT INTO projects(id,name,slug,owner_repo,created_at,updated_at) ... ON CONFLICT(slug) DO NOTHING`.
- Only plain lines are in the Note body and FTS index now. Searching a directive's text uses
  Task FTS over `original_line`; this is the spec's projection, not a regression.
- The picker, chips and canonical snapshot for unsupported URLs remain #29. Project setup
  is #28; when the registry is empty the capture pane says a project must be registered.
