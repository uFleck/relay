- **What changed** — A `grills` table keyed by `(task_id, revision)` persists the exchange, its questions and answers in order, the live attempt id, the allowed Reference identities and a sanitized failure. A pre-dispatch Task-line edit starts a new revision and keeps earlier transcripts on the Task. `v2::grilling` owns every decision: one fresh attempt per model turn with the exchange replayed from SQLite, the user answer committed before the next attempt is claimed, one validated result per attempt (question or Brief), a link-only decision for missing References, a failed turn preserved for Retry, cancellation that invalidates the attempt but keeps the transcript, and restart recovery. The final turn writes a normal `briefs` row; `dispatch_readiness` and `go_enabled` now cover Grill too, so one closing Go records approval through #34's gate and #36 keeps one readiness query. Grill never enters the Wait-only `awaiting approval` status.
  - The shared runner is agent-aware. `Invocation` carries the agent name and an optional loopback endpoint, with a hand-written `Debug` that cannot print a credential or bearer. The boundary preflight no longer sends an unauthenticated inference request to the configured provider: it validates the CLI's local `debug config` and `debug agents` output, and caches only a proven boundary failure or a success by `(executable, model, agent, grill)` fingerprint, so a missing model, credential, executable or app-data directory is retryable. `debug config` is parsed as the real array of sources (directory and document entries, duplicate documents, and a pathless `info: {}` source); document `info` is validated structurally, an empty Brief MCP map is accepted as omitted, and the Grill bearer is accepted as `***` only in debug output while the on-disk config keeps the env interpolation. `debug agents` is parsed as JSON and permission decisions use the CLI's last-matching-rule semantics: built-in allows before Relay's `*/* deny` are expected, and only the exact `relay_grill_read_reference` allow may follow it.
  - The private config uses a single `relay-grill` agent with deny-all plus the exact tool allow, a remote MCP server at an ephemeral `127.0.0.1` URL with `oauth: false`, `codemode: false` and `Authorization: "Bearer {env:RELAY_GRILL_BEARER}"`, and the negative `-opencode.tool.skill` plugin directive. The bearer is two UUIDs injected only into the child environment. `grilling_mcp` binds `127.0.0.1:0`, checks Host, Origin and a constant-time bearer comparison before reading any body, caps bodies at 64 KiB, advertises exactly `read_reference`, ignores OpenCode's opaque `_meta`, and authorizes each `referenceId` against the live attempt in core. It serves bounded content or the canonical URL plus unavailable reason, and revokes the bearer and closes the listener on completion, error, cancellation, drop and app exit. It is independent of the v1 routers and credentials.
  - Thin commands `v2_grilling_{view,start,answer,retry,cancel,go,continue_link_only}` feed one shared inline `GrillPanel` in the Task sheet and the Dock. The panel shows the pending question, the full saved exchange, the editable final Brief and one closing Go after project selection; only an unanswered question adds a Grilling item to Needs you. `relay://grilling` keeps both surfaces in sync.
