## What changed

### Settings → Slack

- Status row: dot, status text and a Disconnect button when the connection is configured.
  - `Not connected` (grey dot).
  - `Connecting…` (amber): configured, not yet connected, no error.
  - `Connected as <user> in <team>` (green).
  - `Slack connection failed` (red): configured, with an error.
  - When the connection is configured, a meta line shows `N peers · N open episodes · last event Xm ago · capture paused`.
- Connect form: two `type="password"` inputs (`xoxp-…`, `xapp-…`). It shows when the connection is not configured or has an error. Connect stays disabled until both fields have text.
- Before calling Rust, the form checks the token prefixes. A `xoxb-` token gets a hint and no call.
- Inline errors put a hint in front of the raw code:
  - `invalid_auth`: copy the token again or reinstall the app.
  - `missing_scope`: add `im:read`, `im:history` and `users:read`.
  - `not_allowed_token_type`: one of the tokens is the wrong kind.
- Both inputs clear after a successful connect.
- Note: "DMs only; tokens stay in Windows Credential Manager; see docs/SLACK_SETUP.md", with a link button to `api.slack.com/apps`. The link goes through the existing `openExternal`, which uses the opener plugin. No new dependency.
- DM peers (shown when the connection is configured): a compact list with the name or Slack user id, a `bot` tag, the user id and an `Exclude` checkbox. The checkbox calls `slackSetPeerExcluded` and is disabled while its call is in flight. An empty list shows "No DMs captured yet.".

### Settings → JEV

- Status: `No API key` or `API key saved · <model>`, plus an error.
- A password input and Save. While the key is checked, Save shows a spinner and "Checking key…". The returned error (thrown, or `status.error`) shows inline.
- Clear appears when a key is configured.
- The input clears on success. The stored key is never sent back to the UI.

### Inbox

- Tabs: All / Open / Needs review / Analyzed. They map to `episodesList({ stateFilter: undefined | "open" | "needs_review" | "analyzed", limit: 50 })`. These are the store's exact `EPISODE_STATES` values.
- Each row shows the peer name (or user id), a state chip (open green, waiting/closed muted, analyzed accent, needs review amber), a one-line preview, `N msgs` and `Xm ago`.
- The list reloads on `relay://change` and on window focus.
- Empty states:
  - Slack not configured: "Slack is not connected" with an **Open Settings** link.
  - Configured: "No episodes yet", or "No episodes in this state" when a tab is selected.

### Transcript sheet

- Opens from an Inbox row, from Review → From Slack, or from `/inbox?episode=<id>` (also through `relay://open`). It uses the TaskSheet layout (`.sheet`, `.sh-h`, `.sh-b`, `.sh-f`).
- Esc closes it and returns focus. The task sheet and the episode sheet are exclusive.
- Header: Slack icon, state chip, peer name, `N messages · started <date time> · last Xm ago`.
- Body: the episode summary when there is one, then the messages in `ts` order, oldest first. Each message shows its author (`You` or the peer), date and time, and the `edited`, `backfill` and `deleted` markers. Deleted text is struck through. A message with a permalink gets an "Open in Slack" button.
- Footer: **Analyze now** calls `episodeAnalyze`. The button is disabled with a spinner while the call or a `pending`/`running` job is in flight.
- The footer also shows the job's state chip, route, kind, summary and error. A `pending_agent` job shows "Waiting for an agent…".
- The job shown is the newest one for the episode in `jobsList({ limit: 50 })`, or the job just returned.

### Review → From Slack

- `jobsList({ stateFilter: "pending" })` filtered to `route === "review"`. Each row shows the job summary, `peer · Xm ago` (from `episodeGet`) and a **Transcript** button. The button opens the sheet in place and keeps the Review view.
- The block is hidden when there are no such jobs. Proposal behaviour is unchanged.

### Agents & MCP masking

- The token fields show `••••••••` plus the last 4 characters, with Reveal/Hide (`aria-pressed`) and Copy.
- The snippets show the masked token until that token is revealed. Copy always copies the real token.
- If the clipboard refuses, the copy fallback reveals the token first (`flushSync`) and then selects the block, so Ctrl+C copies the real token.

## Known risks

- No live Slack workspace was available. Connect, the error strings, `slack://status`, peers and transcripts have not been seen with real data. The hints match on substrings of the error codes.
- The clipboard and the Reveal-then-select fallback were not exercised.
- Saving a JEV key costs one real JEV call per Save.
- `McpStatus` still carries the full tokens from Rust. The mask hides them in the window, but the frontend still receives them. PLAN 6's "frontend only sees status and last 4 chars" needs a Rust change, which is outside this package's scope.
- The From Slack filter is literal: `pending` plus `route === "review"`. If Rust sets `route` only on `done` jobs, the block stays empty.
- `FromSlack` calls `episodeGet` once per distinct episode, which returns full transcripts. This is fine for a short queue and wasteful for a long one.
- No visual pass in a browser or the app. The layout was checked only by reading the CSS.
