- **What changed** — #29's URL recognizer now validates Slack timestamps with string math only (ten-digit seconds, six-digit microseconds; compact path timestamps get the decimal point inserted before the last six digits), keeps a reply link's own message timestamp as presentation, and keys identity on channel plus root `thread_ts`. A new v2 migration adds `slack_thread_cache(channel_id, thread_ts, parent_json, replies_json, fetched_at)`; `V2Store::{slack_thread,save_slack_thread}` read and commit the verified parent, ordered replies and Relay fetch time in one transaction, with an incomplete row or failed write leaving a miss. `V2Store::try_begin_thread` is a process-wide, per-thread gate separate from the SQLite write lock and from `SlackState::begin_sync()`; it is released on every outcome and never held across a CLI call. A new `v2::slack_thread` resolver checks SQLite first, then makes at most two one-call attempts through the existing `ToolCall::read_thread`, `build_prompt`, `Runner` and `parse_stream` seam. `RunRequest` gained a per-run `timeout` and a narrowed `tools` allowlist; the Windows `ProcessRunner` uses the requested 30-second thread deadline, kills and reaps a timed-out child, and keeps `MCP_CONNECTION_NONBLOCKING=false`. Stream validation now counts tool calls, flags duplicates and records connector status; the thread path rejects non-`connected` connectors, skipped calls, unexpected tools, altered arguments, duplicate calls, truncated threads and a parent that is not the requested root, and never caches them. `channel_not_found` ends the current attempt with "Not found or not visible to you"; pending, timeout and skipped calls get exactly one immediate retry. The Tauri `slack::thread` runner chooses `ProcessRunner` or a missing-CLI stub, keeps the CLI off the async thread, persists the read-only Lens snapshot, and enlists #30's shared recovery row. `v2_reference_exact` dispatches Slack to this resolver, so the same chip path in Dock and Notebook starts resolution; the editor keeps the Lens open with an immediate linked "fetching…" row and replaces it in place through `relay://reference-change`. Background recovery reuses the same cache-first resolver; a coalesced attempt leaves the recovery row untouched. Slack recovery pauses use a fingerprint derived from the connector status Settings published on explicit refresh, not from `find_claude()` alone, so re-auth resumes a paused link while the binary stays installed and the worker never polls auth.
