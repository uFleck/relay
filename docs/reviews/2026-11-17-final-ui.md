## What changed

### MCP setup sheet (`src/app/McpSetup.tsx`, `src/ipc.ts`)

- `McpStatus` no longer declares `agentToken` / `analystToken`. Nothing in `src/` reads
  them, so the sheet works whether or not Rust still sends them.
- Each token reads `••••••••` (no last 4) until revealed. The grid and both snippets now
  render whenever a status exists; before, they were hidden until both tokens arrived.
- **Reveal** calls `mcpToken(which)`, shows the token and turns into **Hide**. Hide drops
  the token from component state.
- **Copy** (token row and snippet) calls `mcpToken(which)` on click, then writes to the
  clipboard. If the clipboard refuses or is missing, it reveals the token, selects the
  block and reads "Selected · Ctrl+C", as before.
- Snippets show `<agent token>` / `<analyst token>` in the visible JSON. Their Copy builds
  the snippet with the real token. A revealed token also shows in its snippet, which the
  clipboard fallback needs.
- No token is fetched on mount. An empty answer (browser fallback, or no token file yet)
  and a command error both show "Could not read the token: …".

### Transcript sheet (`src/app/Slack.tsx`, `src/styles/app.css`)

- A `failed` job shows its error (or "The analysis failed without an error message.")
  beside a **Retry** button. Retry calls `jobRetry(job.id)`, reads "Requeueing…" with a
  spinner, keeps the returned job, then awaits a reload of the jobs list and the episode.
- `running` / `pending` keep "Analysis running". For `pending_agent`, the main button now
  reads "Waiting for an agent…" and is disabled. The existing explanatory line stays.
- `.jstate-fail` lays the error and the button out in a row. It uses existing tokens, and
  the card keeps `var(--r)` (8px).

### Inbox (`src/app/Slack.tsx`)

- The subtitle reads "Slack is not connected" only when the list is empty and Slack is not
  configured. Otherwise it reads "N captured episodes" (plus "· newest 50" at the cap).

## Known risks

- Reveal, Copy and the clipboard fallback were not exercised in the desktop app. In
  particular, the clipboard write now runs after an awaited IPC call. WebView2 keeps the
  click's user activation for a few seconds, so it should pass. If it does not, the
  fallback selects the token instead.
- No live failed job was retried. The flow assumes `job_retry` returns the requeued job
  (same id) and that a jobs-list reload then shows its new state.
- Until Rust drops `agentToken` / `analystToken` from `mcp_status`, the payload still
  carries them. The UI ignores them.
- No component tests cover these states. The repo's vitest suite has no DOM setup.
