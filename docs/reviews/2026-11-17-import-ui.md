## UI states

Settings → ClickUp
- Loading: "Reading ClickUp status…"; load failure in red.
- Status row: green dot + "Connected", or grey dot + "No token". Clear button only when configured.
- Password field (`pk_…`), Save with spinner and "Checking token…" while the Rust check runs. A thrown error shows in red under the status row.
- Browser: Save shows "ClickUp runs in the desktop app." instead of calling the fallback.
- Note: token is workspace-wide, stored in Windows Credential Manager, Relay only imports and never writes back.

Projects → Import (collapsed by default behind "Import…" so a long project list stays compact)
- Browser: a single note, "Import runs in the desktop app…"; no inputs, so the zero-count fallback is never shown as a result.
- ClickUp row: list id, "Include closed", "Import list". Disabled while running, when the list id is empty, or when no ClickUp token is configured (with a note pointing to Settings).
- GitHub row: owner, repo, "Import open issues". Disabled while running or when either input is empty. GitHub token is optional (public repos work).
- Result inline per row: "Imported N, skipped M" or the error in red.
- Explanation: imported tasks keep a link; re-running skips what exists; no mirroring.
- The snapshot refresh comes from the existing `relay://change` listener; the panel does not refresh anything itself.

## Known risks

- No live ClickUp or GitHub import was run; the UI is verified only by types and build.
- The Rust import fetches one page of 100 items. A list or repo with more items imports only the first page, and the UI does not say so.
- The ClickUp personal token is workspace-wide (every workspace the account can see).
- `ConnectorStatus` has no `error` field, so a token that later stops working only shows up as an import error, not on the status row.
- Owner/repo are not prefilled from the project's repo path (kept simple, per brief).
