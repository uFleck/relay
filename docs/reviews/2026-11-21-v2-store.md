## What changed

Added `relay_core::v2`: a separate `relay-v2.db` opened beside the v1 file, with its own
`application_id` (`0x52454C59`), `user_version` (1), WAL, foreign keys and a 2-second busy timeout.
Boot inspects a file before touching its journal mode and accepts only a blank file or a supported
v2 schema; a v1 or foreign file is rejected without modification. Schema, default settings and
version land in one transaction, and no v1 table is created.

The typed write contract is `V2Store::save_note(PreparedNoteWrite) -> V2Note`. It stores immutable
line ids, line-specific Tasks with frozen `original_line`, ordered line and Task Reference
memberships, a project choice, and an Import ledger keyed independently of the Note. Create is
idempotent on a submission key; Edit checks revision and line ownership; a late failure rolls the
whole write back. Also exposed `register_project`, `list_projects`, `assign_task_project`,
`update_settings`, Import ledger reads and FTS5 search over Note bodies and Task lines.

The Tauri adapter manages `Arc<V2Store>` alongside `Arc<Store>` and registers the async read
command `v2_notebook_snapshot`. No write command is exposed yet; #25 owns the Composer writes.
Legacy Notes, MCP, Slack, GitHub and ClickUp still use the legacy store.

## Known risks

- **Node pin not usable.** `.node-version` asks for 24.4.1; the active binary is `v26.13.1`. `nvm
  list` advertises 24.4.1 but `nvm use 24.4.1` reports "not installed" and `v24.4.1\node.exe` does
  not exist. Both pnpm commands were run on Node 26.13.1.
- **Live GUI smoke not exercised.** No interactive WebView2 devtools session was available for an
  isolated-identifier `pnpm tauri dev` profile, so `v2_notebook_snapshot` was not invoked from a
  running app and the tray Quit/relaunch cycle was not clicked through. The fresh-profile
  invariant is covered by the core file-backed test instead.
- Writes are callable only from Rust at this checkpoint. No IPC write command and no frontend
  consumer exist yet; #25 owns them.
- No v1 data migration, backup, rollback or `PRAGMA user_version` bridge, per the fresh-start
  decision. Removed non-Task lines are retained with a null position rather than deleted, so
  repeated edits accumulate inactive rows.
- `TaskStatus` serializes as snake_case (`needs_project`, `awaiting_approval`), while SPEC-v2.md
  writes some statuses with spaces. This is the typed contract #25 consumes.
