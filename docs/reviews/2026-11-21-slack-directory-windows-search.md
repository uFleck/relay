- **What changed** — `claude_slack::Tool::ListChannels` and fixed-argument `ToolCall::{list_channels,read_window,search_messages}` were added without changing v1 transport semantics. A metadata directory stores conversation id, explicit `Type`-derived kind (a `C` id never implies group DM), name, members and archived flag, plus a single successful-scan clock and resume cursor; `parse_directory_run` validates each call's fixed arguments and cursor against the previous page, rejects repeated cursors, skipped results, non-`connected` connectors and malformed pages, and follows a cursor even on a short page. One invocation makes up to two pages and `scan_directory` resumes from the last validated cursor (60s per invocation, eight-run ceiling). Discoveries from permalinks and searches merge without advancing the clock and never overwrite a known kind, name or member list. A process-wide `try_begin_directory` gate is separate from the per-thread gate. Triggers: startup when the clock is missing or older than seven days, the Settings provider recheck when Slack setup completed outside Relay, and Enter on **Refresh conversations**; progress is emitted on `relay://slack-directory` and failures keep the last directory and freshness time. Picking a conversation creates a distinct `SlackWindow` Reference with UTC selection time and `(selection − 24h, selection]` bounds before its read; `read_window`/`parse_channel` follow cursors until 20 eligible messages, dedupe by ts, sort chronologically and commit frozen content with `ready`, including a successful empty window. The stored bounds and id drive recovery and all later reads; the first successful result is never refreshed. Explicit search adds a stable action row, one Enter-driven request per query per picker session with `keywords:[query]`, `natural_language_query:""`, `response_format:"detailed"`, `include_context:false`, `limit:10` and a 30s backend deadline; a picker-specific parser keeps channel id, message ts, permalink/`thread_ts`, and the first line as a snippet. Results dedupe by canonical thread key, refresh in place, append in Conversations, preserve the highlighted stable row, discard late responses for a closed picker or different query, and note directory metadata without caching snippets as thread content. A connector that rejects context suppression falls back once to detailed default context (the parser reads only hit fields). Picking a hit reuses #32's resolver and the permalink's `thread_ts`. No token or raw Slack body reaches a DTO, event or row.

No live connector, detailed-search zero-hit response, `include_context:false` acceptance, large (>1600 conversation) scan or multi-workspace selection was verified; the context-suppression fallback is covered only by a synthetic stream. Directory links use `slack.com` as the host because the directory tool does not return a workspace host; a multi-workspace org may navigate to the wrong host until #34 supplies it. Slack may edit or delete messages before the first successful window read; the first successful result is then frozen. Frozen bounds are RFC 3339 UTC with millisecond precision while message timestamps are epoch strings; comparison parses both as instants. No tracker, PR, tag or release was touched.
