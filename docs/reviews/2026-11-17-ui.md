## What changed

### UI reconciled with the existing Rust API (no Rust edits)

| Mismatch (HANDOFF.md) | Resolution in the UI |
| --- | --- |
| `hover_place` | `src/hover/place.ts` computes the physical rect `{x, y, width, height}` from the monitor's work area, its scale factor and an anchor (`edge`, `offset` below the work-area top). Expanding keeps the anchor and clamps the 400×540 panel inside the work area, so collapsing returns the tab to the same spot. Called on every layout change (tab/open/collapse, update variant, first data). |
| `relay://open` payload | Typed as a route string. `src/route.ts` parses `/review`, `/settings`, `/today?task=…&focus=changes`, `/review?proposal=…`; `App` navigates on it. The hover uses `open_main({ route })` for task/review/settings links and `show_main_window()` (no args) for "Open Relay". |
| `show_main_window({ target })` | Removed; `showMainWindow()` sends no args. |
| Updater | `startUpdateChecks()` runs once in `App`. The main window owns the updater and broadcasts its state on `update://state`; the hover calls `followUpdates()` and reads it with `useUpdater()`. The hover's Restart emits `update://install`, which the main window honours only in the `ready` state. The main window shows an update notice in the rail and an Updates section in Settings. |

### Hover (`hover.html`, `src/hover/*`)

- Multi-entry Vite build; `pnpm build` emits `dist/hover.html`.
- Calls `hover_ready` after the first placement; listens to `relay://state` for pinned/DND/paused/visible; pin and DND go through `hover_set_pinned` / `set_dnd`.
- Hover-to-expand polls `hover_pointer` every 50 ms while the window is visible; collapse waits 400 ms and is off while pinned or dragging.
- Drag from the header or grip calls `hover_drag`, then snaps to the nearer side edge of the monitor it landed on and saves `{edge, offset}` per monitor name in `localStorage`.
- `hover_focus` is wrapped but never called: the hover has no field that needs the keyboard.
- States: tab (Today count, amber needs-you badge or `↑` for a ready update), expanded idle, expanded needs-you (proposal cards + unacked changes, `+N more`), update row (available / downloading / ready), loading and data-unavailable tab.
- Pulse: 3 beats when a new proposal or unacked change id appears, on `relay://change` or the 20 s refresh; DND suppresses it, the badge stays.
- The hover never approves: the compact proposal card's only action is Review → `open_main("/review?proposal=…")`.

### Main window

- Inbox, Projects, Agents, Review and Settings render real snapshot data or honest empty states (no invented data; Inbox only has a count in the snapshot and says so).
- Review: the full queue, Approve/Edit/Reject through `decide_proposal` with the task's current rev; `A`/`E`/`R` act on the routed or top proposal; buttons disable while a decision is in flight.
- Task sheet opens from `?task=` (any view) and closes with Esc, returning focus to where it came from. Acks disable while in flight.
- After an ack or a decision the main window emits `relay://change`, so the hover refreshes its counts.
- Loading and load-error screens (with Try again), an in-app error toast for failed commands (no native dialogs), "1 project / 2 projects" pluralization, the dead "More" button in the sheet removed.
- Today layout unchanged; grouped rows still carry no status pill; hover and header counts both come from `todayScope`.

## Known risks

- **Tauri-only paths are unexercised.** Placement, `hover_pointer` polling, `hover_drag` + snap, `relay://open` navigation, `relay://state`, cross-window update events and `decide_proposal` / `ack_change` against the real store were type-checked and unit-tested at the math level only.
- **Monitor/DPI.** Sizes are CSS px × the anchor monitor's `scaleFactor`. A drag onto a monitor with a different scale re-reads that monitor after the drop, but the frame before the re-place may be mis-sized. 100 % / 150 % was not checked on hardware. Monitors with no OS name are not saved.
- **Tab visibility.** The tab is fully visible (52 px), matching Rust's default placement, not the mockup's 26 px peek.
- **No Rust change feed.** Rust does not emit `relay://change`; the hover refreshes every 20 s and on events the main window sends, and the main window refreshes on focus.
- **Recovered files.** `src/app/**`, `src/components/**`, `src/data/**`, `src/model.ts`, `src/types.ts` and the styles come from the post-incident recovery; they type-check and build, but no seeded visual pass ran in this package.
- `src/data/mock.ts` still exports `mockUpdateReady`, now unused.
