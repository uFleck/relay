## What changed

- **`src/ipc.ts`:** `McpStatus` (`running, port, url, analystUrl, error, agentToken, analystToken`), `mcpStatus()` over `invoke("mcp_status")`, and `onMcpStatus()` for `mcp://status` (added to the typed `Events` map). The browser and missing-command fallback is a stopped status on port 38547 with null tokens and no error.
- **`src/App.tsx`:** holds the status. It subscribes to `mcp://status` before it calls `mcp_status`, so a status Rust emits in between is not lost. It passes the status to the Rail and Settings only in Tauri (`null` in the browser, the same as the hover flags).
- **`src/app/McpSetup.tsx`:** the Settings section and `mcpDotState()` (ok / retrying / down), which the Rail also uses.
- **`src/app/Views.tsx`:** the "Agents & MCP" section sits between Hover and Sources.
- **`src/app/Rail.tsx`:** an `MCP` dot after the sync dots. "no sources yet" still shows when there are no sources, whatever MCP's state is.
- **`src/styles/app.css`:** `.mcp` grid, `.snip`, `.mcp-note`, `.mcp-err`. Plain CSS with existing tokens, `var(--r)` (8px) on code blocks, and `user-select: text` on values (the window sets `user-select: none`).

## UI states

| State | Settings → Agents & MCP | Rail |
| --- | --- | --- |
| Browser (`pnpm dev`) | "MCP setup is available in the desktop app." | no MCP dot |
| `running:false`, no error | amber blinking dot, "MCP is starting…"; updates on `mcp://status` | amber blinking `MCP` |
| `running:false`, error, tokens null (token files unreadable) | red dot, "MCP did not start", error text, **Retry** | red `MCP` (title = error) |
| `running:false`, error, tokens set (port taken) | as above, plus the URLs, tokens and snippets | red `MCP` |
| `running:true` | green dot, "Running on 127.0.0.1:38547", URLs, tokens with Copy, both snippets | green `MCP` (title = URL) |

Every state ends with "Tokens are local to this machine. They only open Relay's loopback server on 127.0.0.1."

**Retry** calls `mcp_status` again. Rust starts the server in the background and has no restart command, so Retry only re-reads the status.

**Copy** (tokens and both snippets) calls `navigator.clipboard.writeText`. On success the label is "Copied" for 2.4 s. If the call rejects or throws, the code block is selected and the label is "Selected · Ctrl+C". No native dialogs.

Snippets:

- Executor: `{ "mcpServers": { "relay": { "type": "http", "url": <agent url>, "headers": { "Authorization": "Bearer <agent token>" } } } }`, to merge into `C:\Projects\executor-bridges\servers.json`, then `node sync.mjs` in that folder. The shape matches the existing `hopper` entry there.
- OpenCode: `{ "mcp": { "relay-analyst": { "type": "remote", "url": <analyst url>, "enabled": true, "headers": { "Authorization": "Bearer <analyst token>" } } } }`, to merge into the analyst session's `opencode.json`.

## Known risks

- **Clipboard permissions:** WebView2 should allow `writeText` from the app origin, but this was not exercised in the desktop app. The select-and-Ctrl+C fallback covers a refusal.
- **Tokens visible in the DOM:** both bearer tokens are rendered as plain text in Settings and in the snippets. They are loopback-only, but anyone who can see the screen or inspect the webview can read them. There is no reveal or mask toggle.
- **Tauri-only path not exercised:** in the browser the section shows only the desktop-app note. Nothing ran the running, starting or error states against a live `mcp_status` or `mcp://status`. They are checked only by types and by reading `mod.rs`.
- **Starting state with no event:** if the server never finishes starting and never emits, the UI shows "MCP is starting…" with no Retry. That matches the brief: Retry appears only with an error.
- The OpenCode snippet shape follows OpenCode's documented `mcp` remote config. It was not tested against an OpenCode run.
