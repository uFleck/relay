## What changed

The route union is now `notebook`, `tasks` and `settings`. The query-backed location mechanism stays, so a WebView reload of `index.html` restores the logical route. A selected Task uses `/tasks?task=<id>`; a provider recovery destination uses `/settings?provider=<key>` with keys `github`, `clickup`, `slack`, `opencode` and `t3`. Root, retired v1 paths and unknown provider values fall back to Notebook at its heading, while a retired link that still carries `task=<id>` resolves to the Task sheet. Rust's tray now opens Notebook and Tasks instead of Review, and the hover sends `taskRoute`/`notebookRoute` rather than retired proposal links.

The v2 store exposes one workspace read, `V2WorkspaceSnapshot { notes, tasks, projects, settings }`. `tasks` is a flat projection of every Task, including Tasks whose source line was removed, so a filter cannot hide a routed Task. One shared search path resolves standalone `+project` and `@reference` tokens to persisted identities and combines them with literal, case-insensitive SQLite FTS over the Note body and the Task's frozen line. An unknown qualified token returns zero matches; known but unreadable References still resolve locally. No v1 list cap is applied. Both views re-run the filter on the existing cross-window `relay://v2-change` signal, and a sequence guard drops a slow response for an older query.

`Notebook` is a chronological timeline grouped by local creation day, oldest to newest with a ULID tie-breaker, opening on today even when the day is empty. The shared Composer sits at the newest end. A reader already at the bottom follows a new submission; a reader in older Notes keeps their position. Inline edits go through the #25 Composer edit request, which preserves line identity, Tasks and their text, and retains the draft when a save fails. Task branches render by source-line identity; a removed line's Task is shown from its frozen `original_line` inside its source Note. Direct-send and conversion actions are gone.

`Tasks` is a flat filtered list with a minimal read-only sheet for Notebook links. A missing selected id shows a closable state only after the workspace read completes. Escape returns to `/tasks` and focuses the originating row or the Tasks heading. #27 owns the grouped view, full sheet and badge; #28 owns provider setup. The dedicated v2 Settings entry accepts a provider key and keeps the existing updater controls available in the transition. Tracker review flags on #35, #40 and #41 are untouched.

## Exported contracts for #27 / #28

- `v2_workspace_snapshot()` → `{ notes, tasks, projects, settings }`. `tasks` is flat and unfiltered; select a routed Task from it, never from a filtered list.
- `v2_workspace_search({ query })` → `{ query, noteIds, taskIds }`. The caller holds the snapshot and renders matched Notes with full source-line context.
- Both are thin async Tauri commands over `relay_core::v2::{V2WorkspaceSnapshot, WorkspaceSearchResult}`. Errors keep the `{kind, message}` shape.
- `src/workspace.ts` exports `useWorkspace()`, `useWorkspaceFilter(query, version)`, `groupByDay`, `sortTimeline`, `dayKey`, `todayKey`, `nearBottom`, `SIGIL` and the `WorkspaceFilter` type. Both views share the `relay://v2-change` refresh and the stale-response guard there.
- Task sheet mount point: `src/app/Tasks.tsx` exports `Tasks`, `TaskDetail` and `MissingTask`. Rail badge is a `needsYou` prop in `src/app/Rail.tsx`. Settings mount point: `src/app/Settings.tsx` exports `SettingsView({ provider, version, update })`.
- Route helpers: `notebookRoute()`, `taskRoute(id)`, `settingsRoute(provider?)`, `PROVIDER_KEYS`, `parseRoute`, `formatRoute`, `readLocation`, `writeLocation`.

## Known risks

- **Live desktop smoke deferred.** No disposable Windows profile or interactive WebView2 session was available, so the two-date fixture, day headers and initial scroll, filter combinations, inline edit of an older Note, promotion, sheet reload and Escape were not clicked through. The parser, persistence, IPC JSON shapes, filters and promotion rules are covered by automated Windows tests. `cargo check --workspace` covers the new commands but does not launch the UI.
- **No live provider or hardware case.** GitHub, ClickUp, Slack, OpenCode and T3 Code were not contacted; no hardware focus/DPI case was exercised. Settings shows status text only until #28.
- **Workspace read is a fresh aggregation.** `workspace_snapshot` reuses `notebook_snapshot`'s transaction and derives the flat Task list in memory; a very large Notebook re-reads every Note on each refresh. Acceptable for the local single-user v2 store.
- **Project filter on plain Notes.** A Note has no project column; `+project` matches it through a Task's saved project or a literal standalone `+slug` in an editable line.
